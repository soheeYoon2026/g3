## 1. les-docker-image 실측 요약 (2026-08 캠페인, RTX PRO 6000 96GB)

### ΔCd 분해능 (핵심 실측)

golf 보트테일 테이퍼 스윕 — precision, 동일격자 A/B(`fix_boxes` 고정):

| 변형 | Cd | ΔCd vs 기준 |
|---|---:|---:|
| 기준(h1) | 0.1682 | — |
| 테이퍼 4% | 0.1614 | −0.0068 |
| 테이퍼 7% | 0.1578 | −0.0104 (최저) |
| 테이퍼 10% | 0.1606 | −0.0076 |
| 테이퍼 13% | 0.1685 | +0.0003 (기준 복귀) |

**U자 곡선이 단조·물리적으로 분해됨 → 평균 Cd 추정 노이즈는 ~0.003 미만.**
순간 요동 `cd_std`(~0.023)는 시계열 표준편차이지 평균 오차가 아니다 —
둘을 혼동하면 안 된다. 같은 캠페인에서 "솔 리프트" −2.6%,
**"waist 4%: SU2-adjoint 1순위 추천이었으나 LES 실측 −0.2%"** 도 기록됨.

### 한계 (절대값)

- Ahmed 35° 검증: 유동장은 출판 대역 진입(RMS/U∞ 0.106, 원거리 후류 0.038),
  **절대 Cd는 자유류 외삽 0.484 vs 실험 0.26 = +86%.**
- 표면 힘 적분은 줌 내부에서 ~15배 오차로 보류 상태 — Cd는 운동량 결손
  plateau 판독. **따라서 표면 Cp/Cf 라벨(DoMINO 필드 지도)은 현재 LES에서
  못 뽑는다.**
- `speed_kmh`는 메타데이터일 뿐, 솔버는 격자 레짐(u_inf 0.1, 모형 스케일
  Re~10⁵)에서 고정 실행. u_inf 0.14는 발산, 0.12까지 안정. 도로 Re(10⁷)
  절대값과 직접 비교 불가.
- `XLA_FLAGS=--xla_gpu_autotune_level=0` 필수 (autotune이 Cd를 6% 바꿈).

## 2. 결론 — 역할 분담 확정

| 용도 | 소스 | 이유 |
|---|---|---|
| 절대 Cd/Cl + 표면 Cp/Cf 학습 라벨 | **SU2 유지** | LES 절대값 +86% 편향, 표면 적분 보류, Re 불일치. 기존 ~750건 자산 활용 |
| **ΔCd 방향·순위의 정답** (평가 벤치마크·추천 검증) | **LES** | ΔCd ~0.003 분해 실증, adjoint 1순위가 LES서 무효였던 실측 → SU2 단독 ΔCd 라벨은 의심 |
| 최적화 루프 | G3 그라디언트로 후보 생성 + LES 평가 배분은 BO+GP | adjoint 부재는 G2 티어 문제 아님 |

이전 논의에서 "DoMINO 사전학습(DrivAerML=HRLES)과 LES 라벨이 정합"이라
했던 부분은 정정: **이 집의 LES는 아직 절대값·표면장 진실이 아니므로**
절대 라벨 전환은 보류하고, 상대(ΔCd) 진실 역할만 맡긴다.

## 3. 파일럿 3단계

### P0 — LES↔SU2 순위 상관 (½일, GPU ~수 시간)

`compare_su2.py`(Ahmed 38형상 SU2 스윕 vs LBM 순위 비교)가 이미 있으나
결과 수치는 리포지토리에 없음. EC2 기록을 회수하거나 재실행해서
**Spearman을 확보**한다. 이 숫자가 "SU2 ΔCd 라벨을 어느 정도 믿어도
되는가"의 기준선이 된다.

### P1 — 방향 교차검증 캠페인 (GPU ~17h ≈ 하루)

차 1대(v3 test 그룹 중 케이스 많은 계열 또는 NISMO)로:

1. Workbench 제어점 변형 8개 생성 — 4부위 × 안/밖, **크기는 예상 ΔCd가
   0.005 이상**이 되도록 (LES 분해능 ~0.003, G2 수렴 요동 위)
2. 동일 9형상(기준+8변형)을 **G2와 LES 양쪽** 계산
   - LES: precision, 동일격자 A/B 프로토콜, 9런 × 111분 ≈ 16.6 GPU·h
   - G2: 기존 파이프라인, `verify_case_identity.py`로 규약 검증 포함
3. 산출: G2 ΔCd vs LES ΔCd 방향 일치율. 
   - **일치율 높음** → G2 ΔCd 라벨 신뢰, 데이터 생성은 싼 G2로 계속
   - **일치율 낮음** → ΔCd 정답은 LES로 확정, G2 ΔCd 라벨은 강등.
     이 경우 과거 방향 정확도 50%의 원인이 라벨 쪽이었을 가능성이 큼

### P2 — G3-BENCH 변형쌍 세트 (P1 결과에 따라, GPU ~2.5일)

P1에서 정한 정답 소스로 3개 차종 × 10쌍 = 30쌍을 라벨링해
`--pairs` manifest로 동결 → 모든 challenger가 같은 세트로
ΔCd MAE·방향 정확도를 받는 상설 점수판.

## 4. 실행 조건

- precision은 96GB급(AWS G4 박스) 필요. 로컬 데스크톱 GPU로는 불가.
- LES 러너는 STL 단위 자동정규화(m→mm)·차량 자동 스케일 포함 —
  NISMO STL 그대로 투입 가능.
- 시작 전 관문 1(규약 검증)은 그대로 유효 — LES를 쓰더라도 G2 측
  ref_area·step 규약 확인이 선행돼야 P1의 G2 쪽 숫자를 믿을 수 있다.
