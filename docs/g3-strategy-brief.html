02

Reuse or build from scratch?

Adopt the model architecture

The field converged in 2024–26 on "STL → surface-field point operator." Don't reinvent it. Primary: NVIDIA PhysicsNeMo / DoMINO (Apache-2.0 code). MIT fallbacks with zero vendor coupling: neuraloperator / GINO, thuml/Transolver.

Build the parts that are your moat

STL↔point-cloud/SDF sampling, the G1/G2/G4 label pipeline, the FFD-to-objective wiring, serving, OOD detection, and your own trained weights. This is where the defensibility lives — not in the network.

Your decisive advantage: the usual ML-CFD data bottleneck is already paid for. G1/G2/G4 mass-produce (geometry → Cd/Cl + surface fields) labels on your exact target cars. Everyone else has to buy that data; you don't.

03

MVP architecture

geometry in

Point cloud + SDF

STL → area-weighted surface points + normals + a signed-distance field. The identical sampling transform runs at train and inference — no input drift.

model

DoMINO operator

Local point-based neural operator. PointNet scalar regressor as the week-1 harness; graduate to DoMINO for surface fields.

target

Surface p + τw

Predict the surface pressure & wall-shear field, not just scalar Cd — so forces integrate out, gradients stay smooth, and figures render.

Phase 0 spike — already shipped & verified

The full path runs today on CPU without torch: STL → sampling → features → Cd/Cl regression → FFD deform. Smoke test PASS (synthetic val Cd R²≈0.90), 5/5 geometry unit tests green, sampler verified on the 150k-face ahmed_1.stl. Code in g3/.

04

Data & training — why it isn't scary

The ML training is cheap. The expensive input — labeled CFD — is what you already own.

Pretrain on commercial-clean public data (DrivAerML, AhmedML, WindsorML — all CC-BY-SA). Fine-tune on your G1/G2/G4 labels for the target car family. Onboard a new customer's body with a LoRA adapter on ~20 high-fidelity samples — never a full fine-tune (it collapses).

~500 high-fidelity cars already reach Cd R²≈0.95–0.98. Broad multi-family generalisation needs thousands and still degrades — budget per family.

05

Into the optimisation loop

default

Differentiable surrogate

Surrogate is differentiable → autograd dCd/d(FFD δ) → step with optax/Adam, exactly like the existing loop.

safest

Warm-start G2 / G4

Feed G3's predicted shape & field as the initial guess for the adjoint solvers — cuts iterations, and downstream solvers absorb any G3 error.

selective

RL — only when needed

Gymnasium env (action = morph δ, reward = −Cd) for non-differentiable, discrete/topological, or multi-objective search. Not a default — adjoint is cheaper.

08

Top risks

1
Out-of-distribution collapse — the #1 risk
A surrogate trained on one body family degrades hard on arbitrary uploads (published: RegDGCNN R² 0.90 single-family → 0.64 multi-family). Mitigate: cover the design space with your own solvers, flag low-confidence/OOD predictions, route tight cases back to G2/G4, LoRA per family.
2
No physical-plausibility guarantee
Surrogates can emit non-physical fields. Mitigate: optional NS-residual loss as a regulariser; always verify tight-margin designs with G2/G4.
3
Accuracy trails full CFD at decision margins
Not for 1–2 drag-count calls. Mitigate: scope the product to exploration/screening; final judgement stays with the numerical solvers.
4
Licence traps & NVIDIA/GPU lock-in
CC-BY-NC data or the NIM path can block commercial release. Mitigate: a training-data whitelist, self-minted weights, and MIT backbones (GINO/Transolver) kept as a vendor-independent escape hatch.
Bottom line

Adopt DoMINO (PhysicsNeMo, Apache-2.0), train your own weights on DrivAerML + G1/G2/G4 labels, and build only the data & FFD-integration layer. Ship G3 as the sub-second explore-and-accelerate tier. The real moat is that three solvers you already run print unlimited labels — the data bottleneck that's expensive for everyone else isn't for you.
